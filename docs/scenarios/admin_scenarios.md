# Сценарии: Администратор (по новому дизайну)

> Номера экранов Ф-NN, словарь, решения и статусы — в начале `visitor_scenarios.md`. **Модератор** — админ, который проверяет товары; **аудит** — журнал «кто и что сделал».

---

## [SC-ADMIN-01] Вход по логину и паролю

**User Story:** `US-04` · **Must**
**Экраны:** Ф-14, Ф-19
**Основной сценарий:**
1. Админ входит через Ф-14 (Email, Пароль, «Войти»).
2. Система выдаёт токены; роль админа не совмещается с покупателем и продавцом.
3. Открывается админский раздел, например Ф-19 «Все товары». **Путь между «Все товары», «Все заказы», «Начисление бонусов» не показан** — нужно меню.

**Альтернативные:** неверные данные → общая ошибка.
**Критерии (USM):** токены; общая ошибка; только разделы своей роли.

## [SC-ADMIN-03] Создать товар как админ

**User Story:** `US-34` · **Must**
**Экраны:** Ф-19 → Ф-20

**Основной сценарий:**
1. Админ нажимает «Создать» (Ф-19).
2. *На экране Ф-20:* «← Все товары», «Новый товар», поле **«Продавец»** («Аудио Маркет»), «Название», «Цена, бонусы», «Категория», «Описание» (JSON), «Изображения», жёлтая «Создать».
3. Выбирает продавца-владельца, заполняет поля, нажимает «Создать».
4. Система создаёт товар: владелец — выбранный продавец. Статус — «Выставлен» сразу (админ сам модератор, **предложение**).

**Критерии (USM):** админ создаёт товар; владелец — выбранный продавец (**вопрос из USM закрыт макетом**).

## [SC-ADMIN-04] Модерация, правка и скрытие любого товара

**User Story:** `US-35` · **Must** (+ решение 3)
**Экраны:** Ф-19, Ф-21

**Основной сценарий:**
1. *Экран Ф-19:* «Все товары», жёлтая «Создать», строка «Найти товар», карточки: фото, название, «Продавец: Аудио Маркет», «4 990 бонусов», кнопки «Редактировать», «Скрыть», «Архивировать».
2. **Правка:** «Редактировать» → Ф-21 (как у продавца, плюс поле «Продавец»), «Сохранить». Изменения видны в каталоге.
3. **Скрыть:** «Выставлен» → «Скрыт». «Архивировать» → «Удалён».
4. **Модерация (решение 3):** у товара в статусе «На модерации» должны быть «Одобрить» и «Отклонить» **[Макета нет]**. «Одобрить» → «Выставлен» (по остатку). «Отклонить» → окно причины → товар возвращается в **«Черновик»**, продавец видит причину.

**Критерии (USM → обновлено):** админ одобряет/отклоняет; доступ к любому товару.
**Заметки:** **[Дизайн ≠ USM]** в Ф-19 нет ни чипа статуса, ни фильтра «На модерации»; в Ф-21 нет поля «Категория» (в Ф-06 оно есть).

## [SC-ADMIN-05] Видеть все заказы

**User Story:** `US-36` · **Must**
**Экраны:** Ф-11

**Основной сценарий:**
1. *Экран Ф-11:* «Все заказы»; карточки: «Заказ № 1042 · Покупатель: alexey@example.com · 5 880 бонусов · Статус: Создан», «Детали»; «Заказ № 1038 · maria@example.com · 3 290 бонусов · В обработке».
2. Видны заказы **всех** магазинов.

**Критерии (USM):** все заказы, фильтр по статусу, страницы.
**Заметки:** **[Дизайн ≠ USM]** нет фильтров и страниц.

## [SC-ADMIN-06] Менять статус любого заказа

**User Story:** `US-37` · **Must**
**Экраны:** Ф-11 → Ф-12

**Основной сценарий:**
1. «Детали» → *Ф-12:* «Заказ № 1042», «Покупатель», «Итоговая сумма 5 880 бонусов», «Позиции заказа»: «Беспроводные наушники — Аудио Маркет · 4 990», «Бутылка для воды — ЭкоДом · 890»; «Статус заказа» (Создан); «Сохранить статус».
2. Админ выбирает статус и нажимает «Сохранить статус».
3. Система проверяет переход и меняет статус любого заказа; покупатель (Ф-18) и продавцы (Ф-07) видят результат.

**Критерии (USM):** любой заказ по допустимым переходам; результат виден обеим сторонам.
**Заметки:** см. вопрос про общий статус при двух продавцах (SC-SELLER-16).

## [SC-ADMIN-07] Начислить бонусы клиенту

**User Story:** `US-38` · **Must**
**Экраны:** Ф-13

**Основной сценарий:**
1. *На Ф-13:* «Начисление бонусов»; поле «Поиск клиента по email или логину» (alexey@example.com); серый блок «Клиент alexey@example.com — Текущий счёт 12 400 бонусов»; поле «Количество бонусов для начисления» (1 000); жёлтая «Начислить бонусы».
2. Админ находит клиента (SC-ADMIN-08), вводит 1 000, нажимает кнопку.
3. Система увеличивает баланс на **положительную** сумму: 12 400 → 13 400.
4. Клиент видит новый баланс.

**Альтернативные:** ≤ 0 → отказ; не админ → 403.
**Критерии (USM):** ровно на положительную сумму; только админ.
**Заметки:** нет подтверждения, результата («Начислено») и истории; причины и комментария нет (были в старом макете).

## [SC-ADMIN-08] Найти клиента

**User Story:** `US-39` · **Should**
**Экраны:** Ф-13
**Основной сценарий:** админ вводит email или логин в строку поиска; система ищет по тексту; под полем появляется блок «Клиент … Текущий счёт …» (ID и баланс).
**Альтернативные:** не нашли → «Клиент не найден» **[Макета нет]**; несколько совпадений → список **[Макета нет]**.
**Критерии (USM):** поиск по тексту; результат — ID и баланс.
**Заметки:** в блоке видны email и баланс, ID клиента — нет.
