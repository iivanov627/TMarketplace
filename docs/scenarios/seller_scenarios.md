## [SC-SELLER-01] Стать продавцом (регистрация продавца)

**User Story:** `US-02` · **Must**
**Экраны:** Ф-22 → Ф-23 → Ф-24 → Ф-25
**Предусловия:** есть аккаунт покупателя (решение 9: отдельной регистрации продавца нет).

**Основной сценарий:**
1. Человек регистрируется как покупатель (SC-BUYER-01) и в профиле (Ф-23) нажимает «Стать продавцом».
2. *На экране Ф-24:* «← В профиль», «Стать продавцом», подпись «Укажите данные организации. После отправки вы сможете переключаться между ролями»; поля: «Тип организации *» (список, «Общество с ограниченной ответственностью»), «Название организации *», «ИНН *», «Контактное лицо *», «Email *», «Телефон *»; галочка «Принимаю условия для продавцов и согласен на обработку данных»; жёлтая «Отправить и стать продавцом».
3. Заполняет поля, ставит галочку, нажимает кнопку.
4. Система проверяет обязательные поля и ИНН (10 или 12 цифр), добавляет роль «продавец» **к тому же пользователю**.
5. Открывается Ф-25 с зелёным блоком «Теперь вы продавец».

**Альтернативные:** пустое обязательное поле или неверный ИНН → ошибка под полем; галочка не стоит → кнопка неактивна.
**Постусловия:** у пользователя две роли.
**Критерии (USM):** кроме логина и пароля — данные организации; роль «продавец».
**Заметки:** макет закрывает «список полей». Ф-15 и Ф-16 (регистрация с выбором роли и ИНН) — **устаревшие**.

## [SC-SELLER-02] Вход и переключение на роль продавца

**User Story:** `US-04` · **Must**
**Экраны:** Ф-14, Ф-25, Ф-26

**Основной сценарий:**
1. Продавец входит как обычно (Ф-14, SC-BUYER-03) и попадает в режим покупателя.
2. В профиле нажимает вкладку «Продавец».
3. *На экране Ф-26:* «Профиль продавца», вкладки; карточка «ООО «ЭкоДом»» с жёлтым ярлыком «Продавец», поля «ИНН», «Контактное лицо», «Email», «Телефон»; блок «Всё готово к продажам — Добавляйте товары и принимайте заказы…»; жёлтая «Перейти к моим товарам».

**Альтернативные:** неверные данные → общая ошибка.
**Заметки:** какая роль открывается при входе — **[Макета нет]**, предложение: покупатель.

## [SC-SELLER-05] Мои товары

**User Story:** `US-24` · **Must**
**Экраны:** Ф-26 → Ф-09

**Основной сценарий:**
1. На Ф-26 продавец нажимает «Перейти к моим товарам».
2. *На экране Ф-09:* заголовок «Мои товары», справа жёлтая «Создать»; серые карточки: фото, название, цена «4 990 бонусов», кнопки «Редактировать» (жёлтая), «Скрыть», «Архивировать».
3. Система показывает **только товары этого продавца**; удалённые не показываются.

**Альтернативные:** товаров нет → пустой экран с «Создать» **[Макета нет]**.
**Критерии (USM):** только свои, любые статусы.
**Заметки:** **[Дизайн ≠ USM]** на карточках нет чипа статуса (Черновик, На модерации, Выставлен, Скрыт), поиска и фильтров; для скрытого нужна кнопка «Показать».

## [SC-SELLER-06] Создать товар

**User Story:** `US-25` · **Must**
**Экраны:** Ф-09 → Ф-10

**Основной сценарий:**
1. Продавец нажимает «Создать» (Ф-09).
2. *На экране Ф-10:* «← Мои товары», «Новый товар»; поля «Название» («Введите название товара»), «Цена, бонусы» (0), «Категория» («Выберите категорию»), «Описание», «Изображения» с кнопкой «Загрузить изображение»; жёлтая «Создать».
3. Заполняет поля, добавляет фото (SC-SELLER-12). Описание — JSON характеристик (решение 8): в MVP многострочное поле с примером и проверкой JSON (**предложение**).
4. Нажимает «Создать».
5. Система проверяет: название, категория, цена > 0, JSON валиден. Товар получает статус **«На модерации»**, владелец — продавец.
6. Возврат в Ф-09: карточка нового товара.

**Альтернативные:** ошибка поля → красная подпись.
**Критерии (USM → обновлено):** после создания «На модерации»; цена > 0; описание — валидный JSON.
**Заметки:** **[Дизайн ≠ USM]** нет поля «Количество на складе»; нет кнопки «Сохранить как черновик».

## [SC-SELLER-07] Редактировать товар и цену

**User Story:** `US-26` · **Must**
**Экраны:** Ф-09 → Ф-06

**Основной сценарий:**
1. Продавец нажимает «Редактировать» (Ф-09).
2. *На экране Ф-06:* «← Мои товары», «Редактирование товара», фото с кнопкой «Заменить фото», поля «Название», «Цена, бонусы» (4 990), «Категория» (Электроника), «Описание»; кнопки «Скрыть» и «Архивировать», жёлтая «Сохранить».
3. Меняет цену на 4 500, нажимает «Сохранить».
4. Система сохраняет; **старые заказы остаются со старой ценой**.

**Альтернативные:** чужой товар → 403; цена ≤ 0 → ошибка.
**Критерии (USM):** только свои; цена не влияет на старые заказы.
**Заметки:** товар в «Черновик» (после отказа) нужно отправить заново — кнопки «Отправить на модерацию» нет **[Макета нет]**. Вопрос: идёт ли выставленный товар на повторную проверку после правки (по умолчанию нет).

## [SC-SELLER-09] Скрыть товар

## [SC-SELLER-10] Удалить товар, который не заказывали

**User Story:** `US-28` · **Must**
**Экраны:** Ф-09, Ф-06 (кнопка «Архивировать»)
В макете отдельной кнопки «Удалить» нет: товар без заказов и с заказами убирается одним действием «Архивировать» → статус **«Удалён»** (SC-SELLER-11).
**Заметки:** **[Дизайн ≠ USM]** решить, нужна ли физическая очистка записей товара, которого никто не заказывал и не клал в корзину.

## [SC-SELLER-11] «Архивировать» = статус «Удалён»

**User Story:** `US-29` · **Must**
**Экраны:** Ф-09, Ф-06

**Основной сценарий:**
1. Продавец нажимает «Архивировать» у товара.
2. **[Макета нет]** Подтверждение «Убрать товар? Старые заказы сохранятся».
3. Статус → **«Удалён»**: товар исчезает из каталога и «Моих товаров».
4. В старых заказах и в чужих корзинах он остаётся видимым как прошлая позиция (с плашкой «Недоступен»).

**Критерии (USM → обновлено):** удаление запрещено без следа; история сохраняется.
**Заметки:** название кнопки «Архивировать» не совпадает со статусом «Удалён» — переименовать одно из двух.

## [SC-SELLER-12] Загрузить изображение

**User Story:** `US-30` · **Should**
**Экраны:** Ф-10, Ф-06

**Основной сценарий:**
1. В Ф-10 в блоке «Изображения» продавец нажимает «Загрузить изображение» (в Ф-06 — «Заменить фото» рядом с миниатюрой).
2. Выбирает файл в галерее.
3. Приложение отправляет файл отдельным запросом в хранилище S3; система возвращает id файла, он записывается в товар.
4. Рядом появляется миниатюра.

**Альтернативные:** формат или размер не подходят → ошибка **[Макета нет]**.
**Критерии (USM):** отдельный эндпоинт в S3; id в товаре; ограничения — уточнить.
**Заметки:** **[Дизайн ≠ USM]** ограничений формата и размера в новом макете нет; одно фото против «до 5» в прошлом.

## [SC-SELLER-16] Сменить статус своего заказа

**User Story:** `US-33` · **Must**
**Экраны:** Ф-08

**Основной сценарий:**
1. На Ф-08 продавец открывает список «Статус заказа» (сейчас «В обработке»).
2. Выбирает следующий статус, например «Отправлен», и нажимает «Сохранить статус».
3. Система проверяет переход (только вперёд по цепочке Создан → В обработке → Отправлен → Доставлен) и меняет статус.
4. Покупатель видит новый статус в Ф-18.

**Альтернативные:** запрещённый переход → отказ; чужой заказ → 403.
**Критерии (USM):** только разрешённые переходы; чужие — 403; покупатель видит.
**Заметки:** в заказе № 1042 товары двух продавцов (Ф-12), а статус один — **кто меняет статус всего заказа?** Решить: статус на позицию или на заказ.
