# Сценарии: Посетитель (по новому дизайну)

> Основа: `USM_marketplace.md` + новый PDF с макетами (26 экранов) + принятые решения. Каждый шаг: «действие человека → ответ системы → что видно на экране». Старые фреймы (Ф-01…Ф-15 из прошлого PDF) больше не используются.

## Словарь

| Термин | Что значит |
|---|---|
| Посетитель (гость) | Человек, который открыл приложение, но не вошёл |
| Б, бонусы | Внутренняя «валюта» маркетплейса |
| Ф-NN | Номер экрана в новом PDF (таблица ниже) |
| SSR | Сервер отдаёт страницу уже готовой, поэтому поисковик её «читает» |
| 403 / 404 | «Доступ запрещён» / «страница не найдена» |
| **[Дизайн ≠ USM]** | Макет и USM расходятся или в макете чего-то не хватает — нужно решение |
| **[Макета нет]** | Экрана нет; описание сделано по соседнему экрану (предложение, не факт) |

## Принятые решения

| № | Решение |
|---|---|
| 1 | Оплата **и бонусами, и деньгами**; деньги пока **моковые** (демо-оплата). Сначала списываются бонусы, остаток — картой. В новом макете доплата **не нарисована** |
| 2 | Бонусы начисляются **при старте** (при создании аккаунта) |
| 3 | Статусы товара — словарь ниже. После «Отклонить» админом товар **возвращается в «Черновик»**. «Удалён» нужен **только чтобы прошлый товар оставался виден в корзине** (и в заказах) |
| 4 | Счётчик количества «как в дизайне» — **в новом дизайне счётчика нет** (см. SC-BUYER-10) |
| 5 | Гость при «Добавить в корзину» или переходе в корзину попадает на экран регистрации (Ф-22). **В будущем:** хранить корзину в кэше |
| 6 | Отмена: в макете кнопка «Отменить заказ» у заказа в статусе «Создан» (Ф-18). Читаю так: отмена только пока заказ «Создан» (SC-BUYER-21) |
| 7 | Статусы заказа — по аналогии с товаром (словарь ниже) |
| 8 | Описание товара — JSON-строка с характеристиками |
| 9 | Один человек = покупатель + продавец, переключается вкладками (Ф-25, Ф-26). Админ отдельно |

**Статусы товара:**

| Статус | Что значит | Кто видит |
|---|---|---|
| Черновик | Сохранён, не отправлен; сюда же возвращается товар после отказа | владелец |
| На модерации | Ждёт решения админа («Одобрить» / «Отклонить») | владелец, админ |
| Выставлен | Виден в каталоге. Внутри: «В наличии», «Нет в наличии», «В корзине» (отметка для покупателя, у которого товар в корзине) | все |
| Скрыт | Временно убран (кнопка «Скрыть») | владелец, админ |
| Удалён | Снят; в каталоге и «Моих товарах» не показывается, но в старой корзине и заказах остаётся (кнопка «Архивировать» в макете) | только как прошлая позиция |

**Статусы заказа** (в макетах есть «Создан», «В обработке», «Отменён»; остальные — предложение): Создан → В обработке → Отправлен → Доставлен; Отменён.

## [SC-VISITOR-01] Каталог без входа

**User Story:** `US-06` · **Must** · **Актор:** Посетитель
**Экраны:** Ф-01
**Предусловия:** не авторизован.
**Триггер:** открытие приложения (отдельной ссылки «продолжить без входа» в новом макете нет).

**Основной сценарий:**
1. Гость открывает приложение. *На экране Ф-01:* вверху жёлтый значок и «Маркетплейс», справа жёлтая кнопка «⇥ Войти»; заголовок «Каталог»; строка «Найти товар» с лупой; подпись «Цена, бонусы» и два поля «От» и «До»; строка «Все товары» и справа «Сначала дешевле ⌄»; сетка 2 × 2 карточек (фото, цена «890 Б», название); внизу переключатель страниц «‹ 1 2 3 ›»; нижняя панель из четырёх значков: дом, сердце, корзина, человек.
2. Система запрашивает список **без токена** и берёт только товары в статусе «Выставлен».
3. Гость видит каталог. Кнопок «Редактировать» и «Скрыть» нет.

**Альтернативные:** нет товаров → **[Макета нет]** пустое состояние.
**Постусловия:** открыт публичный каталог, данные не меняются.
**Критерии (USM):** открывается без токена; только активные; кнопок редактирования нет.
**Заметки:** на карточках нет бейджей, продавца и кнопки «в корзину» — добавить можно только с карточки товара.

## [SC-VISITOR-02] Страницы и сортировка каталога

**User Story:** `US-07` · **Should**
**Экраны:** Ф-01

**Основной сценарий:**
1. Гость нажимает «2» в переключателе «‹ 1 2 3 ›» (активная страница залита жёлтым, стрелка «‹» на первой странице серая).
2. Система запрашивает вторую страницу (`page`/`size`); сетка заменяется новыми карточками.
3. Гость нажимает «Сначала дешевле ⌄» — открывается список вариантов: «Сначала дешевле», «Сначала дороже» **[Макета нет]**.
4. Система запрашивает `sort=price,asc|desc`; карточки перестраиваются, страница сбрасывается на 1.

**Постусловия:** список показан по страницам и в выбранном порядке.
**Критерии (USM):** пагинация и `sort=поле,asc|desc` по контракту API.
**Заметки:** старая «сортировка по популярности» из прошлого дизайна ушла — теперь по цене, как в USM.

## [SC-VISITOR-03] Находить товары через поисковик

**User Story:** `R2-01` · **Could**
**Экраны:** Ф-02, Ф-03

**Основной сценарий:**
1. Гость вводит в Яндексе/Google название товара и нажимает ссылку на маркетплейс.
2. Сервер отдаёт страницу **уже собранной (SSR)**, поисковик заранее её проиндексировал.
3. Открывается карточка (Ф-02).
4. Если товара больше нет в статусе «Выставлен» → страница 404 (Ф-03: большой «404», «Страница не найдена», «Запрашиваемая страница не существует», кнопка «Вернуться в каталог»).

**Критерии (USM):** публичный каталог отдаётся с SSR.
**Заметки:** макеты выглядят как веб-страницы, значит веб-версия вероятна; подтвердить.

## [SC-VISITOR-04] Поиск товара по тексту

**User Story:** `US-09` · **Must**

## [SC-VISITOR-05] Фильтры по названию и цене

**User Story:** `US-10` · **Must**
**Экраны:** Ф-01

**Основной сценарий:**
1. Гость вводит в «От» 1000 и в «До» 3000 (поля под подписью «Цена, бонусы»).
2. Система отправляет `f[price]=1000,3000` (вместе с названием — `f[name]=…`).
3. В каталоге остаются «Настольная лампа, 2 490 Б» и подобные.

**Альтернативные:** «От» больше «До» → подсветка поля ошибкой **[Макета нет]**.
**Критерии (USM):** `f[name]` и `f[price]=от,до` работают отдельно и вместе.
**Заметки:** кнопки «Применить» в макете нет — фильтр должен срабатывать при вводе или по Enter (решить).

## [SC-VISITOR-06] Карточка товара

**User Story:** `US-11` · **Must**
**Экраны:** Ф-01 → Ф-02

**Предусловия:** товар в статусе «Выставлен».

**Основной сценарий:**
1. Гость нажимает карточку «Беспроводные наушники».
2. Система возвращает карточку без токена.
3. *На экране Ф-02:* «← В каталог»; крупное фото; название и цена «4 990 Б»; серая плашка «Продавец — Аудио Маркет»; блок «Описание» с текстом; жёлтая кнопка «🛒 Добавить в корзину» и под ней серая подсказка «Войдите, чтобы добавить товар».
4. **Описание (решение 8):** хранится JSON-строкой, например `{"Описание":"Беспроводные полноразмерные наушники…","Подключение":"Bluetooth","Цвет":"графитовый"}`; приложение выводит её текстом или строками «ключ: значение».

**Альтернативные:** статус не «Выставлен» → Ф-03 (404). «Нет в наличии» → кнопка серая **[Макета нет]**.
**Критерии (USM):** карточка без входа; невыставленный — «не найден».
**Заметки:** **[Дизайн ≠ USM]** в макете описание — обычный абзац; как он получается из JSON, надо договориться (список ключей).

## [SC-VISITOR-07] Добавить в корзину без входа

**User Story:** `US-14` · **Should**
**Экраны:** Ф-02, Ф-22, Ф-14

**Основной сценарий:**
1. Гость нажимает «Добавить в корзину» (Ф-02) **или** значок корзины в нижней панели.
2. Система не добавляет товар, а переводит на экран регистрации Ф-22 («Регистрация — Один аккаунт для покупок и продаж», поля Email, Пароль, Повторите пароль, жёлтая «Зарегистрироваться», ссылка «Уже есть аккаунт? Войти», серый блок «Хотите продавать?»).
3. Гость регистрируется (SC-BUYER-01) или нажимает «Войти» → Ф-14 (SC-BUYER-03).
4. После входа возвращается на карточку этого товара (Ф-02, уже без подсказки «Войдите…»); товар не добавлен — нужно нажать кнопку ещё раз.

**Альтернативные:** «← В каталог» — гость остаётся гостем.
**Критерии (USM):** гость уходит на вход; после входа возвращается на карточку.
**Заметки:** то же для значков «Избранное» и «Профиль» (**предложение**).
